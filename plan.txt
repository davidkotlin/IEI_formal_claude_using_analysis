### 低耦合設計原則

- routes/：只負責接收請求、回傳回應，不寫計算邏輯
- services/：負責所有計算邏輯，不知道 Flask 存在
- models/：負責資料庫操作，不知道業務邏輯
- frontend/api/index.js：集中管理所有 API 呼叫，元件不直接打 API

換資料庫 → 只改 models/
換計算邏輯 → 只改 services/
前端換框架 → 只改 api/index.js

## API 端點設計

### 共用查詢參數
- start_date：string，格式 YYYY-MM-DD
- end_date：string，格式 YYYY-MM-DD
- users：string，逗號分隔的用戶名稱

### 端點列表

#### GET /api/users
回傳所有用戶名單，給篩選器用。

回傳：
```json
{
  "total": 167,
  "users": ["Alex Chien", "Angela Lee", ...]
}
```

#### GET /api/users/inactive
回傳篩選條件內未使用的用戶名單。

查詢參數：start_date, end_date, users

回傳：
```json
{
  "count": 82,
  "inactive": ["Alex Chien", ...]
}
```

#### GET /api/stats/summary
回傳區間總結指標。

查詢參數：start_date, end_date, users

回傳：
```json
{
  "active_users": 85,
  "total_users": 167,
  "active_pct": 50.9,
  "rounds": {
    "mean": 46.1,
    "median": 32.0,
    "mode": 16
  },
  "duration_median": 11.2
}
```

#### GET /api/stats/ranking
回傳各人排名資料。

查詢參數：start_date, end_date, users, metric（messages / duration / tools）

回傳：
```json
{
  "metric": "messages",
  "data": [
    {"name": "Eva Chang", "value": 320},
    {"name": "Kimmie Hsieh", "value": 280},
    ...
  ]
}
```

#### POST /api/import
接收 users.json 與 conversations.json，匯入 db，已存在的對話自動跳過。

請求：multipart/form-data
- users：users.json 檔案
- conversations：conversations.json 檔案

回傳：
```json
{
  "success": true,
  "conv_inserted": 66,
  "conv_skipped_dup": 0,
  "conv_skipped_unknown": 0,
  "conv_skipped_weekend": 10,
  "conv_skipped_empty": 8
}
```

#### GET /api/stats/hourly
回傳時段分析資料（00:00-23:00）。

查詢參數：start_date, end_date, users

回傳：
```json
{
  "data": [
    {"name": "Eva Chang", "hours": [0, 0, 0, ..., 3, 1, 0]},
    ...
  ]
}
```

## 資料庫 Schema

### users 表
| 欄位 | 型別 | 說明 |
|------|------|------|
| uuid | TEXT PK | Anthropic 帳號 UUID |
| full_name | TEXT | 姓名 |
| email | TEXT | 信箱 |

### conversations 表
| 欄位 | 型別 | 說明 |
|------|------|------|
| uuid | TEXT PK | 對話 UUID |
| user_uuid | TEXT FK | 對應 users.uuid |
| name | TEXT | 對話標題 |
| created_at_tw | TEXT | 開始時間（台灣時間） |
| updated_at_tw | TEXT | 結束時間（台灣時間） |
| duration_min | REAL | 時長（分鐘） |
| total_messages | INTEGER | 總訊息數 |
| tool_use_count | INTEGER | 工具呼叫次數 |
| weekday | INTEGER | 星期幾（0=週一） |
| hour | INTEGER | 發生小時 |
| date | TEXT | 發生日期 YYYY-MM-DD |

## 未來換 PostgreSQL 注意事項

目前 db_process.py 用原生 sqlite3 操作資料庫，Flask 用 SQLAlchemy ORM 讀取，
兩套系統共用同一個 monitor.db，未來換 PostgreSQL 時需要同步修改：

1. config.py 的連線字串：
   ```python
   # 改成
   SQLALCHEMY_DATABASE_URI = "postgresql://user:password@localhost/iei_claude"
   ```

2. db_process.py 改用 SQLAlchemy 操作（方式二重構）：
   - 移除原生 sqlite3 import
   - get_connection() 改用 SQLAlchemy session
   - init_db() 改用 db.create_all()
   - INSERT OR IGNORE 改用 SQLAlchemy merge() 或 on_conflict_do_nothing()

3. cron_import.py 不需要改，只呼叫 db_process.py 的函式

換資料庫建議時機：正式上線前，一次完成 db_process.py 重構 + PostgreSQL 遷移。

## 部署注意事項

### 首次部署流程
1. 回到乾淨快照
2. 設定時區：`sudo timedatectl set-timezone Asia/Taipei`
3. 執行 `sudo ./setup_ubuntu22.sh`
4. 前端 build：`cd frontend && npm run build`
5. 重啟服務：`sudo systemctl restart iei_claude`

### 每次更新前端後
```bash
cd /opt/IEI_claude_using_analysis
git pull
cd frontend
npm run build
```
不需要重啟 Nginx，build 完 Nginx 自動服務新的 dist/。

### Nginx 上傳限制
預設只允許 1MB，conversations.json 遠超過限制，需在 Nginx 設定加：
```nginx
server {
    client_max_body_size 200M;
    ...
}
```
設定檔位置：`/etc/nginx/sites-available/iei_claude`
改完執行：`sudo nginx -t && sudo systemctl restart nginx`

### SQLite 刪除檔案行為
Linux 刪除 monitor.db 後，只要 Gunicorn worker 還活著連線還開著，
短時間內程式還能讀寫資料（Linux 檔案系統特性，移除目錄連結但檔案內容還在）。
重啟 Gunicorn 後才會真正找不到 db。
手動匯入會重新建立 monitor.db，所以不需要重啟服務。

## 備註

- 時長定義：updated_at - created_at，是對話總跨度，非實際使用時間
- 週末（六日）資料不匯入
- 未知/已刪除帳號資料不匯入
- pending 用戶不會出現在 users.json，無需處理
- SQLite → PostgreSQL 只需改 config.py 的連線字串，其餘不動
